# Moon globe view: design (FE, T10 + T18)

Date: 2026-11-14 · Owner: FE · Status: draft, awaiting approval

## Intent
First screen of the app. A 3D Moon you can orbit, with the candidate landing sites marked on it.
A slider picks the **landing date**; every site is recoloured by how good a mission starting that day would be.
Answers "the launch slipped two weeks, which site is best now?" for mission planners, educators and the public.

## Goals
- Orbit camera (rotate, zoom, pan limits) around a textured Moon; initial view looks at the south pole.
- Site markers at their real lat/lon, coloured by the selected landing date's score.
- Landing-date slider stepping through `matrix.json` `landing_dates_utc`.
- Hover/select a site: name, date, the metric values; uncertainty note from the file.
- Runs fully offline from static files.

## Non-goals (for this step)
- Close-up terrain view, sky panorama, timeline, compare board (later views).
- Lighting the globe by the real Sun position for the date (possible later, needs a sun-direction field from AERO).
- Any physics in the front end.

## Anti-goals
- A score or colour that looks authoritative but comes from fake data: fixtures must say FIXTURE in the UI.
- A metric shown without its source/uncertainty.

## Constraints
- Contract v0.1 (`contracts/`): reads `manifest.json`, `sites.json`, `matrix.json`.
- Offline demo, no tokens, no live API.
- Sites cluster near the south pole. Equirectangular textures pinch at the poles, so the pole is the weakest
  part of a textured sphere. Mitigation below.

## Approaches considered
- **A. three.js globe with NASA SVS CGI Moon Kit textures** (chosen): offline, no token, small, fully stylable.
  Blurry when zoomed far in on one site; acceptable for picking sites, close-up is a separate view later.
- B. Streamed Cesium Moon / 3D tiles: smooth zoom to crater scale, but needs ion token + internet (breaks offline rule) and is heavier.
- C. Flat polar map: rejected, user wants an orbit camera.

## Decisions
- Stack: Vite + React + TypeScript, @react-three/fiber + drei (`OrbitControls`), Zustand for the store
  (selected landing date index, selected metric, hovered/selected site). Styling: plain CSS with tokens (no Tailwind) — FE call.
- Textures (NASA SVS 4720 "CGI Moon Kit", credit "NASA's Scientific Visualization Studio"; aesthetic, not science):
  - colour: `lroc_color_poles_4k.tif` converted once to JPG/WebP,
  - relief: `ldem_16_uint.tif` → downsampled 8/16-bit PNG used as displacement/normal map for grazing-light relief.
  - Conversion is a small script in `frontend/scripts/` (FE-owned; only display assets, not analysis data).
    Converted files go in `frontend/public/textures/` (checked in if < ~10 MB total, else git-ignored + fetch script).
- South-pole quality: start with the equirectangular sphere and check how the pole looks. If smeared,
  add a polar-cap mesh (polar-stereographic texture made by the same script) over the pole. Decide after seeing it.
- Lighting: one directional "sun" at a fixed grazing angle for looks, plus faint ambient. Black background. Not data-driven (labelled as illustrative).
- Colouring: until AERO's `docs/PARAMETERS.md` exists, colour by one `matrix.cells` field chosen in a dropdown,
  default `both_frac`. Sequential colour scale, `null` = grey "no data". Replace with AERO's combined score later.
- Data location: loaders read from a base URL; default `/fixtures/` (FE fixtures), switch to real data via
  `VITE_DATA_BASE`. How `data/processed/` gets into the build (copy vs symlink) is decided when real files land.
- Loaders validate against zod mirrors of the v0.1 schemas and check `contract_version`; mismatch → visible error, not silent.
- Fixtures: `manifest.json`, `sites.json` (3–5 sites, fake coordinates near the pole, `coord_source: "FIXTURE"`),
  `matrix.json` (sites × ~30 daily landing dates, values in range, some `null`), generated by a small script so they can be regenerated.

```
┌──────────────────────────────────────────────────────────┐
│ BOPE Lunar Navigator            metric: [both_frac ▾]  FIXTURE │
│                                                          │
│                     (orbitable Moon)                     │

│  └──────────────────────────────────────────────────┘    │

```

## Left to the builder
Marker shape/size, colour scale choice, camera limits, slider styling, texture resolution trade-off (4k vs 8k).

## Verification
- `npm run build` passes; Vitest for loaders (valid fixture passes, wrong version fails) and lat/lon→xyz.
- Fixtures pass `python contracts/validate.py frontend/public/fixtures`.
- Manual: dev server shows globe, markers at the pole, slider recolours markers.
